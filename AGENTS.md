# AGENTS.md

## Cursor Cloud specific instructions

### What this is
Single product ("Skoolio", repo `media-voti`, previously Aulera / Spaggiari 2): a FastAPI backend (`main.py`) plus a
static vanilla-JS frontend (`public/`) and a SQLite DB. It is an unofficial client for the
Italian ClasseViva/Spaggiari school register. Python deps are in `requirements.txt`
(installed into `.venv` by the update script). The `package.json` is only for the optional
Capacitor Android build (`android/`, `capacitor.config.json`, `app-shell/`) and is not needed
to run the web app. Build: `npm install && npx cap sync android && cd android && ./gradlew
assembleDebug` (JDK 21 + Android SDK 35; in Claude cloud containers Maven Central may return
429 — a Gradle init script pointing at `https://maven-central.storage-download.googleapis.com/maven2/` works).

### Running the app (dev)
Run the backend from the repo root with the venv, e.g.:

```
DEV_MODE=true \
ALLOWED_ORIGINS="http://localhost:8000,http://127.0.0.1:8000" \
DATABASE_PATH=/tmp/spaggiari2data/spaggiari2.db \
COOKIE_SECURE=false \
.venv/bin/python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

With `DEV_MODE=true` a single Uvicorn process on `:8000` serves `public/` AND rewrites
`/api/*` → `/*` (mirrors the production Nginx setup), so no separate frontend server is
needed. See `README.md` / `scripts/dev-windows.ps1` for the split-server alternative
(uvicorn on `:8000` + `python -m http.server 5500 --directory public`).

### Non-obvious gotchas
- ACCESS THE DEV APP AT `http://127.0.0.1:8000`, NOT `http://localhost:8000`.
  `public/config.js` treats `hostname === "localhost"` as the Capacitor embedded app and
  points all API/WebSocket calls at the PRODUCTION server
  (`https://spaggiari2.federicoscutariu.it`). Using the `127.0.0.1` IP keeps requests on the
  local backend.
- `DATABASE_PATH` should point OUTSIDE the repo in dev (e.g. under `/tmp`). The committed
  `data/spaggiari2.db*` files are git-tracked and have a stale schema; letting the app write
  to them dirties the working tree. `init_db()` runs on FastAPI startup and creates all
  current tables (`CREATE TABLE IF NOT EXISTS`), so a fresh DB file is fully provisioned on
  first boot.
- Core functionality (login, grades, absences, leaderboards) requires REAL ClasseViva
  student credentials — an external dependency reached at `https://web.spaggiari.eu`.
  The ClasseViva client lives in `classeviva_client.py` (`WebSessionUtente`: PHPSESSID cookie
  against `/rest/w1`; `RequestURLs` keeps the `/rest/v1` paths, rewritten to w1).
- Since Sept 2026 (Legge 182/2025) many schools allow ClasseViva access ONLY via SPID/CIE,
  so username/password login no longer works for those users.
  `scripts/check_spid_session.py` checks whether a SPID-obtained web session (`PHPSESSID`)
  is usable from the server; run it manually with your own session, it is not automated.
- Frontend: single-page app, no build step. `public/index.html` has an import map with versioned
  URLs (`aulera/ui`, `aulera/api`, `aulera/state`, `aulera/grades`, `aulera/main`); views live in
  `public/app/views/*.js` and are loaded with the same `?v=` as `main.js`. BUMP the version in the
  import map / CSS links when changing frontend files. Never import shared modules by relative path
  from views (it would create a second module instance). `scripts/dev_fake_server.py` runs the app with
  a fake ClasseViva (login via the dev cookie field with any 16+ char value).
- Sessions (`session_store.py`) last 30 days and are persisted in SQLite (`auth_sessions`, ClasseViva
  cookie encrypted with `AULERA_SECRET_KEY` or the generated `aulera-secret.key` next to the DB);
  a background keep-alive thread pings ClasseViva every `CLASSEVIVA_KEEPALIVE_SECONDS` and records
  lifetimes in `cvv_session_stats` (admin → "Durata sessioni ClasseViva"). Tests should set
  `CLASSEVIVA_KEEPALIVE_SECONDS=0`.
- `notifications.py` (sync with ClasseViva from the keep-alive thread, `/notifiche*` API, `public/app/notify.js`)
  and `friends.py` (`/amici*`) are APIRouter modules included at the end of `main.py`; they access main via
  `import main as core` inside functions. Synced user preferences: `GET/PUT /preferenze` (`state.setPrefs`).
  Agenda ICS feed: `POST /calendario-feed`, `GET /calendario/{token}.ics`. The Android app also has a WorkManager
  `NotificationWorker` polling `/api/notifiche` every 15 min. `.github/workflows/ios-ipa.yml` builds an unsigned IPA.
- Grade colors: green ≥ 6.5 (`g-top` filled + shine ≥ 9), yellow-green `--six` 6–6.49, red < 6, `g-fire` < 4 (small
  flames above the pill, as wide as it, from an animated SVG generated by `scripts/generate_fire.py`), plus `g-devil`
  horns < 3. Grade pills have a fixed width (`.grade` 44px, `.grade-sm` 34px); averages use `.grade-avg` (auto width). Tapping a grade opens
  `public/app/grade-detail.js` (`aulera/gradedetail`): confetti/rays celebration ≥ 9, "how to get back to 6" when low.
- Performance: after boot `main.js` prefetches every view module in idle time and registers `public/sw.js`
  (cache-first for `/app|/styles/*?v=`, stale-while-revalidate for `/assets` and `/vendor`; never `/api` or HTML;
  old `?v=` entries are pruned). In the native app the `api.js` data cache uses localStorage (instant reopen),
  on the web sessionStorage. View Transitions and the SVG "liquid glass" filter are desktop-only (they drop frames
  on high-DPI phones).
- Brand: the two originals are in `brand/` (app icon + horizontal logo); `scripts/generate_brand.py` regenerates
  favicon, apple-touch icon, `public/assets/skoolio-logo(-dark).png` (white text for dark theme, dark text for light),
  Android launcher/adaptive icons and splash, iOS AppIcon and splash. Re-run it after changing the originals.
- Username/password login was removed (ClasseViva is SPID/CIE-only); the admin panel relies on the
  SPID session plus optional `ADMIN_PANEL_PASSWORD`.
- SPID/CIE support (see `docs/spid-cie.md`): `WebSessionUtente` authenticates with the
  ClasseViva web cookie against `/rest/w1` (same paths/payloads as `/rest/v1`). The Android
  app (`android/`, Capacitor 7, loads the live site via `server.url`) captures the cookie
  after the official login with the native `SpaggiariLogin` plugin + `public/spid-app.js`; PCs are linked
  from the phone via QR/code (`/pair/*`, page `public/collega/`). To try it locally without
  the app, run with `ALLOW_MANUAL_WEB_SESSION_LOGIN=true` and use the dev field in the
  SPID panel of the login page (needs a real `PHPSESSID`).

### Tests / lint / build
- Automated self-check: `.venv/bin/python scripts/test_session_me_cache.py`. It imports
  `main` directly and does NOT run the startup `init_db()`, so it needs a DB that already
  has the tables — run it with `DATABASE_PATH` pointing at a DB the app has already booted
  against, otherwise it fails with `no such table: user_badges`.
- `scripts/test_web_session_pairing.py` tests web-session login, PC pairing and device
  revoke with a mocked Spaggiari (no network).
- There is no lint config (no ruff/flake8/eslint) and no build step for the web app; the
  frontend is served as static files.
